# Skill: Художественный перевод книг (EN→RU)

Навык для перевода **полноценных художественных книг** (фэнтези, sci-fi, проза)
с английского на русский. Разбивает книгу на чанки с уважением к границам
глав, переводит их параллельными субагентами, следит за терминологией через
глоссарий с обратной связью, применяет грамматическую + литературную
обработку, и собирает финальный FB2 напрямую на Python (без Pandoc — для
корректного форматирования изображений, глав, сносок, эпиграфов).

Этот файл — **lean-оркестратор**. Детальные инструкции каждого шага
вынесены в `references/phase-{1,2,3}-*.md` и читаются агентом по мере
продвижения по пайплайну. Это критично для устойчивости к сжатию контекста.

## ⚠️ RESUME-ПРОТОКОЛ (читай первым делом, особенно после сжатия)

**Перед любой работой — определи, где ты находишься:**

```bash
python3 {baseDir}/scripts/shared/load_state.py "<temp_dir>"
```

Скрипт печатает:
- `current_step` — номер текущего шага (1-9, или 10 = всё готово)
- `current_phase` — фаза (1, 2, или 3)
- `completed_steps` — список завершённых шагов
- `notes` — последние заметки от предыдущих шагов
- путь к файлу с детальными инструкциями текущей фазы

**После загрузки state** — прочитай файл текущей фазы (см. таблицу ниже)
и продолжай с `current_step`.

**После завершения каждого шага — обязательно сохраняй state:**

```bash
python3 {baseDir}/scripts/shared/save_state.py "<temp_dir>" <step_number> \
    --note "что было сделано" \
    [--set key=value ...]
```

`progress.json` живёт в `<temp_dir>/progress.json` (human-facing root).
Это **единственный** файл, который гарантированно переживает сжатие
контекста с полной точностью — все важные состояния должны быть в нём
или в других персистентных файлах (`glossary.json`, `голос_книги.md`,
`run_state.json`, `manifest.json`).

## Структура пайплайна (9 шагов в 3 фазах)

| Фаза | Шаги | Что происходит | Файл инструкций |
|------|------|----------------|-----------------|
| **1. Подготовка** | 1, 2, 3 | EPUB → Markdown-чанки, структурные units, глоссарий, голос | `references/phase-1-prepare.md` |
| **2. Перевод** | 4, 5, 6 | План, параллельный перевод субагентами, merge meta в глоссарий | `references/phase-2-translate.md` |
| **3. Финал** | 7, 8, 9 | Verify, QA, pronoun, polish, quality_check, post-mortem, сборка FB2 | `references/phase-3-finish.md` |

**Точки обязательного сжатия контекста:**
- После шага 3 (после правки глоссария пользователем) — перед фазой 2
- После шага 6 (после перевода всех глав) — перед фазой 3

Подробнее: `references/compaction-points.md` (читается по мере надобности).

## Главный принцип: оркестратор — не исполнитель

**Главный агент (ты) — только оркестратор.** Ты запускаешь скрипты,
спавнишь субагентов для LLM-работы, читаешь их результаты, принимаешь
решения по merge. **Никогда не делай LLM-работу сам** — не переводи
чанки, не полируй, не делай QA, не определяй рассказчика.

| Правильно | Неправильно |
|-----------|-------------|
| Спавнить субагента для перевода чанка | Переводить чанк в своём контексте |
| Спавнить субагента для polish чанка | Полировать чанк в своём контексте |
| Спавнить субагента для QA чанка | Делать QA в своём контексте |
| Запускать скрипт `merge_meta.py` | Читать meta-файлы и мержить вручную |
| Запускать скрипт `run_state.py plan` | Проходить по чанкам и решать вручную |

**Почему это критично:**
1. **Контекст оркестратора ограничен.** Если переводить 200 чанков самому —
   контекст переполнится, авто-сжатие потеряет критичные части SKILL.md.
2. **Субагент работает в свежем контексте** — видит только свой чанк,
   промпт, и инъецированные данные. Никакого дрейфа от предыдущих чанков.
3. **Параллелизм** — 4-8 субагентов работают одновременно, ты только
   собираешь результаты.

**Исключения** (когда главный агент делает LLM-работу сам):
- Решение `decisions_needed` в `merge_meta.py` (быстрый выбор option).
- Создание `голос_книги.md` и первичного `glossary.json` на шаге 3
  (если пользователь не предоставил заранее).

## Философия: скрипты — структура, агенты — смысл

| Что | Чем делается |
|-----|--------------|
| Разбить книгу на чанки | Скрипт (`phase1_prepare/convert.py`) — детерминированно |
| Проверить SHA-256, fingerprint, валидация | Скрипт |
| Найти эпиграф/сноску по паттерну | Скрипт (`phase1_prepare/detect_epigraphs.py`) |
| Сгруппировать чанки по heading'ам | Скрипт (`phase1_prepare/narrator_marker.py`) |
| Собрать данные для диагностики | Скрипт (`phase3_finish/pronoun_check.py`, `post_mortem.py`) |
| **Определить, кто рассказчик в чанке** | **LLM-агент** (`prompts/phase2_translate/определение_рассказчика.md`) |
| **Установить род персонажа** | **LLM-агент** (через `attribute_hypotheses` в meta) |
| **Решить, как переводить культурную отсылку** | **LLM-агент** (`prompts/phase2_translate/эпиграф_обработка.md`) |
| **Найти конфликты местоимений между чанками** | **LLM-агент** (`prompts/phase3_finish/сверка_местоимений.md`) |
| **Оценить качество прогона** | **LLM-агент** (`prompts/phase3_finish/пост_мортем.md`) |
| **Применить грамматические/литературные правки** | **LLM-агент** (`prompts/phase3_finish/полировка_чанка.md`) |

Скрипты никогда не угадывают семантику. Если нужно угадать — передаём LLM.

## Глобальные инварианты (применимы ко всем шагам)

1. **Оркестратор — не исполнитель.** Никогда не переводит/не полирует/не QA сам.
2. **Все важные состояния на диске.** `glossary.json`, `голос_книги.md`,
   `progress.json`, `manifest.json`, `run_state.json`, `chunk_sections.json`,
   `narrator_hints.json`, `structural_units.json`. Эти файлы — источник
   истины; ничего критичного не должно оставаться только в контексте
   разговора.
3. **После каждого шага — пиши `progress.json`** через `save_state.py`.
   Это обязательный контракт, без него resume после compaction сломается.
4. **Скрипты — структура, агенты — смысл.** Скрипты детерминированы;
   семантику (POV, род, культурные отсылки) решает LLM-агент.
5. **Перед каждой LLM-работой через субагента** — собери данные через
   скрипты; не подгружай чанки в свой контекст (раздувает контекст
   оркестратора, провоцирует auto-compact).
6. **Windows + PowerShell** — если ты на Windows, обязательно прочти
   `references/windows-powershell.md` ПЕРЕД началом работы. Кратко: не
   используй `python3 -c` с циклами/генераторами (молча не работает на
   PowerShell); пиши временные `.py` файлы в `<temp_dir>/process/`.
7. **Шаг 3 — СТРОГАЯ ПАУЗА.** После сборки глоссария (шаг 3) —
   **ОБЯЗАТЕЛЬНО остановись и жди подтверждения пользователя.** Не
   продолжай к шагу 4 (перевод) автоматически, даже если пользователь
   сказал «переведи книгу» в первом сообщении. Ошибки в глоссарии
   размножатся на все чанки и потребуют полного повторного перевода.
   Сообщи пользователю: глоссарий собран, вот ключевые термины, проверь
   и ответь «продолжить». **Только после явного «продолжить» — запускай
   шаг 4.** Не интерпретируй молчание, «ок» или общие фразы как согласие.
8. **Проверяй файлы на диске, а не отчёты субагентов.** Субагент может
   отчитаться «записал 78 терминов и проверил», когда на диске лежит
   пустой или битый файл. После **любой** записи `glossary.json` (своей
   или субагента) — обязательный шлюз:
   ```bash
   python3 {baseDir}/scripts/phase1_prepare/glossary.py validate-glossary "<temp_dir>"
   ```
   Схема `glossary.json` (top-level `"version": 2` обязателен, `id`
   генерируется скриптом) — `references/meta-json-schema.md`, Часть 1.
   Правка `glossary.json` — только через
   `scripts/shared/edit_glossary_template.py`, никогда `str.replace`/sed.

## Критерии качества (итоговые)

1. Текст читается как естественная русская проза (не калька)
2. Сохранён голос рассказчика (тон, ирония, обращения к читателю)
3. Терминология соответствует словарю (100% по must-приоритету)
4. Диалоги живые, с разнообразными глаголами речи
5. Голос каждого персонажа соответствует его описанию (если задано)
6. Грамматика без ошибок (все 20 категорий)
7. ALL CAPS адекватно обработаны
8. Структура FB2 корректна и проходит XSD-валидацию: главы как
   `<section>`, изображения как `<image xl:href="#_img_N"/>` +
   `<binary>`, сноски как `<a xl:href="#note_N">` + `<body name="notes">`,
   эпиграфы как `<epigraph>` в начале секции
9. Character ratio RU/EN в пределах 0.6–2.0
10. Непредвиденных английских фрагментов нет (>5 слов подряд)

## Типичные ошибки (избегать)

- **Не менять смысл** — не добавлять и не убирать сюжетные детали
- **Не «улучшать» автора** — не добавлять отсебятину
- **Не переводить обратно в английский строй** — русский текст самодостаточен
- **Не смягчать грубый/провокационный юмор**, если он — часть стиля
- **Не оставлять многостраничный ALL CAPS**
- **Не сглаживать голос рассказчика**
- **Не делать реплики персонажей «одинаково причёсанными»**
