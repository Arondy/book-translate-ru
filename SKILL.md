# Skill: Художественный перевод книг

Навык для перевода полноценных художественных книг с английского на русский:
фэнтези, sci-fi, проза. Книга режется на чанки по границам глав, чанки
переводят параллельные субагенты, терминологию ведёт глоссарий с обратной
связью, дальше идут грамматическая и литературная обработка и сборка
финального FB2 на Python без Pandoc, чтобы корректно оформить изображения,
главы, сноски и эпиграфы.

Этот файл - lean-оркестратор. Детальные инструкции каждого шага вынесены в
`references/phase-{1,2,3}-*.md` и читаются агентом по мере продвижения по
пайплайну, поэтому они переживают сжатие контекста.

---

## RESUME-протокол

Читай этот раздел первым делом, особенно после сжатия контекста. Перед любой
работой определи, где ты находишься:

```bash
python3 {baseDir}/scripts/shared/load_state.py "<temp_dir>"
```

Скрипт печатает:
- `current_step` - номер текущего шага (1-9, или 10 = всё готово)
- `current_phase` - фаза (1, 2, или 3)
- `completed_steps` - список завершённых шагов
- `notes` - последние заметки от предыдущих шагов
- путь к файлу с детальными инструкциями текущей фазы

**После загрузки state** прочитай файл текущей фазы из таблицы ниже и
продолжай с `current_step`.

**После каждого шага сохраняй state:**

```bash
python3 {baseDir}/scripts/shared/save_state.py "<temp_dir>" <step_number> \
    --note "что было сделано" \
    [--set key=value ...]
```

`progress.json` живёт в `<temp_dir>/progress.json`. После сжатия контекста он
читается первым и восстанавливает картину с полной точностью, поэтому все
важные состояния должны лежать на диске: в самом `progress.json` или в других
персистентных файлах (`glossary.json`, `голос_книги.md`, `run_state.json`,
`manifest.json`).

## Структура пайплайна

Пайплайн - 9 шагов в 3 фазах.

| Фаза | Шаги | Что происходит | Файл инструкций |
|------|------|----------------|-----------------|
| **1. Подготовка** | 1, 2, 3 | EPUB/FB2 в Markdown-чанки по H1/H2, структурные units: эпиграфы и сноски, глоссарий, голос книги | `references/phase-1-prepare.md` |
| **2. Перевод** | 4, 5, 6 | План прогона, параллельный перевод субагентами, транзакционный merge meta в глоссарий | `references/phase-2-translate.md` |
| **3. Финал** | 7, 8, 9 | Verify, QA, сверка местоимений, полировка, пост-мортем, сборка FB2 | `references/phase-3-finish.md` |

Сжатие контекста обязательно в двух точках:
- после шага 3, когда пользователь проверил глоссарий, перед фазой 2
- после шага 6, когда переведены все главы, перед фазой 3

Подробнее - `references/compaction-points.md`, читается по мере надобности.

## Главный принцип: оркестратор - не исполнитель

Главный агент (ты) только оркестратор. Ты запускаешь скрипты, спавнишь
субагентов для LLM-работы, читаешь их результаты, принимаешь решения по merge.
**Никогда не делай LLM-работу сам** - не переводи чанки, не полируй, не делай
QA, не определяй рассказчика.

| Правильно | Неправильно |
|-----------|-------------|
| Спавнить субагента для перевода чанка | Переводить чанк в своём контексте |
| Спавнить субагента для polish чанка | Полировать чанк в своём контексте |
| Спавнить субагента для QA чанка | Делать QA в своём контексте |
| Запускать скрипт `merge_meta.py` | Читать meta-файлы и мержить вручную |
| Запускать скрипт `run_state.py plan` | Проходить по чанкам и решать вручную |

Почему это критично:

1. Контекст оркестратора ограничен. Переведёшь 200 чанков сам - контекст
   переполнится, авто-сжатие потеряет критичные части SKILL.md.
2. Субагент работает в свежем контексте: видит только свой чанк, промпт и
   инъецированные данные, поэтому стиль не дрейфует от предыдущих глав.
3. Параллелизм: 4-8 субагентов работают одновременно, ты только собираешь
   результаты.

Исключения, когда главный агент делает LLM-работу сам:

- решение `decisions_needed` в `merge_meta.py`, быстрый выбор option
- создание `голос_книги.md` и первичного `glossary.json` на шаге 3, если
  пользователь не предоставил их заранее

## Философия: скрипты - структура, агенты - смысл

| Что | Чем делается |
|-----|--------------|
| Разбить книгу на чанки | Скрипт (`phase1_prepare/convert.py`), детерминированно |
| Проверить SHA-256, fingerprint, валидация | Скрипт |
| Найти эпиграф/сноску по паттерну | Скрипт (`phase1_prepare/detect_epigraphs.py`) |
| Сгруппировать чанки по heading'ам | Скрипт (`phase1_prepare/narrator_marker.py`) |
| Собрать данные для диагностики | Скрипт (`phase3_finish/pronoun_check.py`, `post_mortem.py`) |
| **Определить, кто рассказчик в чанке** | **LLM-агент** (`prompts/phase2_translate/определение_рассказчика.md`) |
| **Установить род персонажа** | **LLM-агент** (через `attribute_hypotheses` в meta) |
| **Решить, как переводить культурную отсылку** | **LLM-агент** (`prompts/phase2_translate/эпиграф_обработка.md`) |
| **Найти конфликты местоимений между чанками** | **LLM-агент** (`prompts/phase3_finish/сверка_местоимений.md`) |
| **Оценить качество прогона** | **LLM-агент** (`prompts/phase3_finish/пост_мортем.md`) |
| **Применить грамматические/литературные правки** | **LLM-агент** (`prompts/phase3_finish/полировка_чанка.md`) |

Скрипты никогда не угадывают семантику. Если нужно угадать - передаём LLM.

## Глобальные инварианты

Эти правила действуют на всех шагах.

1. Оркестратор - не исполнитель. Никогда не переводит, не полирует и не
   делает QA сам.
2. Все важные состояния на диске: `glossary.json`, `голос_книги.md`,
   `progress.json`, `manifest.json`, `run_state.json`, `chunk_sections.json`,
   `narrator_hints.json`, `structural_units.json`. Это источник истины,
   ничего критичного не остаётся только в контексте разговора.
3. После каждого шага пиши `progress.json` через `save_state.py`. Это
   обязательный контракт, без него resume после compaction сломается.
4. Скрипты - структура, агенты - смысл. Скрипты детерминированы, семантику
   (POV, род, культурные отсылки) решает LLM-агент.
5. Перед каждой LLM-работой через субагента собери данные скриптами. Не
   подгружай чанки в свой контекст: он раздуется, и сработает auto-compact.
6. Windows + PowerShell: прочти `references/windows-powershell.md` до начала
   работы. Не используй `python3 -c` с циклами и генераторами, на PowerShell
   они молча ничего не выводят; пиши временные `.py` файлы в
   `<temp_dir>/process/`.
7. **Шаг 3 - строгая пауза.** После сборки глоссария остановись и дождись
   подтверждения пользователя. Не переходи к шагу 4 автоматически, даже если
   в первом сообщении было «переведи книгу»: ошибки в глоссарии размножатся
   на все чанки, и перевод придётся повторять целиком. Сообщи пользователю:
   глоссарий собран, вот ключевые термины, проверь и ответь «продолжить».
   Молчание, «ок» и общие фразы согласием не считаются.
8. Проверяй файлы на диске, а не отчёты субагентов. Субагент может
   отчитаться «записал 78 терминов и проверил», когда на диске лежит пустой
   или битый файл. После любой записи `glossary.json`, своей или субагента,
   обязательный шлюз:
   ```bash
   python3 {baseDir}/scripts/phase1_prepare/glossary.py validate-glossary "<temp_dir>"
   ```
   Схема `glossary.json` описана в `references/meta-json-schema.md`, Часть 1:
   обязательный top-level `"version": 2`, `id` генерирует скрипт. Правь
   `glossary.json` только через `scripts/shared/edit_glossary_template.py`,
   никогда `str.replace` или sed.

## Критерии качества

1. Текст читается как естественная русская проза (не калька)
2. Сохранён голос рассказчика (тон, ирония, обращения к читателю)
3. Терминология соответствует словарю (100% по must-приоритету)
4. Диалоги живые, с разнообразными глаголами речи
5. Голос каждого персонажа соответствует его описанию (если задано)
6. Грамматика без ошибок (все 20 категорий)
7. ALL CAPS адекватно обработаны
8. Структура FB2 корректна и проходит XSD-валидацию: главы как
   `<section>`, изображения как `<image xl:href="#_img_N"/>` +
   `<binary>`, сноски как `<a xl:href="#note_N">` + `<body name="notes">`,
   эпиграфы как `<epigraph>` в начале секции
9. Character ratio RU/EN в пределах 0.6–2.0
10. Непредвиденных английских фрагментов нет (>5 слов подряд)

## Типичные ошибки

- Не менять смысл: не добавлять и не убирать сюжетные детали
- Не «улучшать» автора: не добавлять отсебятину
- Не переводить обратно в английский строй, русский текст самодостаточен
- Не смягчать грубый и провокационный юмор, если он часть стиля
- Не оставлять многостраничный ALL CAPS
- Не сглаживать голос рассказчика
- Не делать реплики персонажей «одинаково причёсанными»
