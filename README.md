# book-translate-ru

Навык для AI-агентов: художественный перевод EN-RU. Режет EPUB и FB2 на чанки по границам глав, переводит их параллельными субагентами с общим глоссарием, прогоняет через грамматическую и литературную полировку и собирает FB2.

## Обзор

`book-translate-ru` — skill для платформ с [Agent Skills](https://agentskills.io/): Claude Code, OpenAI Codex, GitHub Copilot, Kilo Code и других. Проводит книгу через три фазы:

**Подготовка.** Конвертирует исходник в Markdown и режет на чанки по H1/H2. По умолчанию один чанк — одна глава. Вытаскивает эпиграфы, сноски и структуру. Собирает глоссарий и фиксирует голос книги.

**Перевод.** Субагенты переводят чанки батчами по 4–8 за раз. Каждый получает таблицу терминов, контекст соседей и промпт перевода. Новые термины, алиасы и гипотезы о роде персонажей мержатся в глоссарий транзакционно после каждого батча.

**Финал.** Структурная и смысловая проверки, сверка местоимений, пофрагментная полировка по 20 грамматическим и 14 литературным категориям. Пост-мортем и сборка FB2 на Python с валидацией по XSD.

## Архитектура

1. Подготовка: EPUB - чанки - структурные units - глоссарий - голос книги
2. Перевод: План - батчи субагентов - merge meta - глоссарий
3. Финал: Verify - QA - pronoun - polish - quality_check - post-mortem - FB2

Оркестратор не делает LLM-работу сам. Он запускает скрипты, порождает субагентов и читает их результаты. Весь перевод, QA, полировку и пост-мортем делают субагенты в свежем контексте.

Состояние пайплайна лежит в `progress.json` на диске. После сжатия контекста агент запускает `load_state.py`, смотрит текущий шаг, читает инструкции фазы из `references/` и продолжает.

## Установка

### Требования

| Инструмент | Назначение |
|---|---|
| Python 3.10+ | Скрипты пайплайна; 3.11+ предпочтительнее из-за встроенного `tomllib` |
| Pandoc | EPUB/FB2 - Markdown на этапе конвертации исходника |
| `beautifulsoup4`, `lxml` | Устанавливаются через `pip install -r requirements.txt` |

FB2 собирает `fb2_builder.py` через `lxml`.

### Установка навыка

Скопируйте директорию `book-translate-ru/` в папку skills вашей платформы:

- **Общее решение:** `~/.agents/skills/book-translate-ru/`
- **Claude Code:** `~/.claude/skills/book-translate-ru/`
- **Kilo Code:** `~/.kilo/skills/book-translate-ru/`

## Использование

### Быстрый старт

Укажите агенту путь к книге:

> Переведи книгу `MyBook.epub` на русский.

Агент проведёт книгу через все три фазы. На шаге 3 он поставит паузу, покажет собранный глоссарий и попросит проверить терминологию перед переводом. После подтверждения переводит батчами, затем полирует и собирает FB2.

Результат: `<книга>_temp/book.fb2` и `post_mortem.md` с анализом качества.

### Серия книг

Если книга — часть серии и есть переводы предыдущих томов, укажите агенту пути к ним. Агент изучит стиль, терминологию и обращения к читателю и закрепит единую схему в `словарь_терминов.md` и `голос_книги.md`. Подробнее в `references/phase-1-prepare.md`, раздел 1.1.

### Возобновление после сжатия контекста

```bash
python3 scripts/shared/load_state.py "<temp_dir>"
```

Скрипт покажет текущий шаг, фазу и путь к файлу с инструкциями. Агент прочитает нужный `references/phase-N-*.md` и продолжит.

## Конфигурация

Основные настройки в `config.toml`. Скопируйте его в рабочую директорию рядом с `<книга>_temp/` и правьте под конкретную книгу, или же используйте базовый вариант без изменений.

## Ключевые особенности

### Resume-протокол

Состояние в `progress.json`. После compact агент запускает `load_state.py`, видит `current_step: N`, читает файл текущей фазы из `references/` и продолжает. Каждая фаза лежит в отдельном файле и загружается по мере необходимости.

### Глоссарий с обратной связью

Субагенты предлагают новые термины в `meta.json`. `merge_meta.py` мержит их транзакционно: либо применяются все изменения, либо ни одного. `find-duplicates` находит близкие дубликаты: единственное и множественное число, краткие и полные имена, пересечения алиасов. После каждого батча новые термины уходят на проверку пользователю.

`glossary.json` защищён от разрушающих записей. Поле `version: 2` в корне обязательно. Скрипты не заменяют существующий глоссарий пустым дефолтом и не пишут пустой список терминов поверх непустого. `validate-glossary [--fix]` обязателен после каждой записи. Он проверяет схему, обязательные поля, уникальность и подсвечивает одноразовые термины с `frequency` 0–1. Поле `id` генерируется из английского названия автоматически (`Tracker's Lenses` - `trackers_lenses`).

Субагенты добавляют новые термины с `confidence: "low"`. Пользователь подтверждает вариант командой `confirm-terms` (`--all`, `--source` или `--id`). Она поднимает уверенность до `high`, безопасно сериализует JSON, дописывает `notes: "confirmed by user"` и не трогает уже подтверждённые термины:

```bash
python3 {baseDir}/scripts/phase1_prepare/glossary.py confirm-terms "<temp_dir>" --all
python3 {baseDir}/scripts/phase1_prepare/glossary.py confirm-terms "<temp_dir>" --source "Brightsand"
```
