# book-translate-ru

Навык для AI-агентов: художественный перевод книг с английского на русский. EPUB и FB2 разбиваются на чанки по границам глав, переводятся параллельными субагентами с ведением глоссария, проходят грамматическую и литературную полировку, после чего собираются в FB2.

## Обзор

`book-translate-ru` — skill для платформ, поддерживающих [Agent Skills](https://agentskills.io/): Claude Code, OpenAI Codex, GitHub Copilot, Kilo Code и другие. Навык проводит книгу через три фазы:

**Подготовка.** Исходный файл конвертируется в Markdown, разбивается на чанки по границам H1/H2. По умолчанию один чанк — одна глава. Извлекаются эпиграфы, сноски, структурные единицы. Собирается глоссарий и формируется голос книги.

**Перевод.** Чанки переводятся субагентами батчами по 4–8 за раз. Каждый субагент получает терм-таблицу, neighbour context и промпт перевода. Наблюдения субагентов — новые термины, алиасы, гипотезы о роде персонажей — мержатся в глоссарий транзакционно после каждого батча.

**Финал.** Структурная проверка, содержательная QA-проверка, сверка местоимений, пофрагментная полировка с 20 грамматическими и 14 литературными категориями. Пост-мортем анализ, сборка FB2 напрямую на Python с XSD-валидацией.

## Архитектура

```
[1. Подготовка]  EPUB → чанки → структурные units → глоссарий → голос книги
       ↓
[2. Перевод]     План → батчи субагентов → merge meta → глоссарий
       ↓
[3. Финал]       Verify → QA → pronoun → polish → quality_check → post-mortem → FB2
```

Оркестратор не делает LLM-работу сам. Он запускает скрипты, порождает субагентов, читает их результаты. Весь перевод, QA, полировка и пост-мортем выполняются субагентами в свежем контексте — это защищает от дрейфа качества на длинных книгах.

Состояние пайплайна хранится в `progress.json` на диске. После сжатия контекста агент запускает `load_state.py`, определяет текущий шаг, читает файл соответствующей фазы из `references/` и продолжает работу.

## Установка

### Требования

| Инструмент | Назначение |
|---|---|
| Python 3.10+ | Скрипты пайплайна; 3.11+ предпочтительнее из-за встроенного `tomllib` |
| Pandoc | EPUB/FB2 → Markdown на этапе конвертации исходника |
| `beautifulsoup4`, `lxml` | Устанавливаются через `pip install -r requirements.txt` |

FB2-сборка идёт напрямую на Python через `fb2_builder.py` с использованием `lxml`. Pandoc на этом этапе не нужен.

### Установка навыка

Скопируйте директорию `book-translate-ru/` в папку skills вашей платформы:

- **Claude Code:** `~/.claude/skills/book-translate-ru/`
- **Kilo Code:** `~/.kilo/skills/book-translate-ru/`
- **OpenAI Codex:** по спецификации Agent Skills

## Использование

### Быстрый старт

Укажите агенту путь к книге:

> Переведи книгу `C:\Books\MyBook.epub` на русский.

Агент определит задачу и проведёт книгу через все три фазы. На шаге 3 произойдёт пауза — агент покажет собранный глоссарий и попросит проверить терминологию перед началом перевода. После подтверждения перевод выполняется батчами, затем полировка и сборка FB2.

Результат: `<книга>_temp/book.fb2` и `post_mortem.md` с анализом качества.

### Серия книг

Если переводимая книга — часть серии и есть переводы предыдущих книг, укажите агенту пути к ним. Агент изучит стиль, терминологию, обращения к читателю и закрепит единую схему перевода в `словарь_терминов.md` и `голос_книги.md`. Подробнее — в `references/phase-1-prepare.md`, раздел 1.1.

### Возобновление после сжатия контекста

```bash
python3 scripts/shared/load_state.py "<temp_dir>"
```

Скрипт покажет текущий шаг, фазу и путь к файлу с инструкциями. Агент прочитает нужный `references/phase-N-*.md` и продолжит.

## Конфигурация

Основные настройки в `config.toml`:

```toml
[chunking]
chunk_size = 30000          # Целевой размер чанка в символах
chapter_only = true         # Один чанк = одна глава

[quality]
ratio_min = 0.6             # Минимальное соотношение длины RU/EN
ratio_max = 2.0
en_leak_chars = 80          # Порог непереведённого ASCII-рана

[polish]
ratio_min = 0.5             # Соотношение polished/raw
ratio_max = 2.0
max_heading_delta = 2       # Допустимое изменение числа заголовков

[parallelism]
batch_size = 4              # Рекомендуемый размер батча
```

Скопируйте `config.toml` в рабочую директорию рядом с `<книга>_temp/` и правьте под конкретную книгу.

## Ключевые особенности

### Resume-протокол

`progress.json` — единственный файл, который гарантированно переживает сжатие контекста без потерь. После compact агент запускает `load_state.py`, видит `current_step: N`, читает файл текущей фазы из `references/` и продолжает. Каждая фаза — отдельный файл, загружаемый по мере необходимости. Это позволяет переводить большие книги без потери состояния.

### Глоссарий с обратной связью

Субагенты предлагают новые термины в `meta.json`. Скрипт `merge_meta.py` мержит их транзакционно — либо все изменения применяются, либо ни одного. Команда `find-duplicates` находит близкие дубликаты: единственное/множественное число, краткие и полные имена, пересечения алиасов. После каждого батча новые термины показываются пользователю для проверки.

`glossary.json` защищён от разрушающих записей: top-level `"version": 2` обязателен, скрипты никогда не подменяют существующий глоссарий пустым дефолтом и не пишут пустой список терминов поверх непустого. Команда `validate-glossary [--fix]` — обязательный шлюз после любой записи в глоссарий: проверяет схему, обязательные поля, уникальность, а также подсвечивает одноразовые термины (`frequency` 0–1). Поле `id` каждого термина генерируется из английского названия автоматически (`Tracker's Lenses` → `trackers_lenses`).

Субагенты добавляют новые термины с `confidence: "low"`. Когда пользователь подтверждает вариант, подними уверенность до `"high"` штатной командой `confirm-terms` (по `--all`, `--source` или `--id`), которая безопасно сериализует JSON, дописывает `notes: "confirmed by user"` и не трогает уже подтверждённые термины:

```bash
python3 {baseDir}/scripts/phase1_prepare/glossary.py confirm-terms "<temp_dir>" --all
python3 {baseDir}/scripts/phase1_prepare/glossary.py confirm-terms "<temp_dir>" --source "Brightsand"
```

### Сборка FB2

Прямой Markdown → FB2 на `lxml.etree`, без Pandoc. Главы становятся `<section>`, изображения — `<image>` с бинарными данными в `<binary>`, сноски — отдельное `<body name="notes">`, эпиграфы — `<epigraph>` в начале секции. Результат валидируется по XSD-схеме FictionBook 2.0, после чего форматируется скриптом `pretty_fb2.py`: каждый абзац на одной строке, структурные элементы с отступами.

### Windows и PowerShell

Инлайн `python3 -c` с циклами и генераторами молча возвращает пустой вывод на PowerShell. Навык требует писать любой код сложнее одного выражения в `.py` файл. Для `apply-merge` предусмотрен шаблон `apply_merge_template.py` с прямым вызовом функции через Python import, обходя stdin. Ошибки `WinError 5` при атомарной записи — ожидаемое поведение, скрипт автоматически откатывается к неатомарной записи.
